## 二、定期维护（每月 1 次，30 min）

### 2.1 更新 New-API

```bash
cd /opt/newapi

# 拉取最新镜像
docker compose pull new-api

# 重启（数据保留在 MySQL 卷里）
docker compose up -d

# 查看启动日志
docker compose logs -f --tail 50 new-api
```

### 2.2 查看用量趋势

后台 → **用量查询** → 选时间段

**重点关注**：
- 哪个模型用量最大 → 是否可以替换为更便宜的
- 哪个平台错误率高 → 是否需要加备用渠道
- 是否有异常峰值 → 是否被刷

### 2.3 数据库备份

```bash
# 自动备份脚本（已配置）
bash /opt/newapi/scripts/backup.sh

# 备份文件位置
ls -lh /opt/newapi/backups/
```

### 2.4 清理旧日志

```bash
# Docker 日志清理
docker system prune -a

# Nginx 日志清理
sudo journalctl --vacuum-time=30d
```

## 三、异常处理预案

### 3.1 故障速查表

| 现象 | 可能原因 | 解决方法 | 耗时 |
|------|---------|---------|------|
| **Dashboard 打不开** | 容器挂了 / 端口占用 | `docker compose ps` → 重启 | 5 min |
| **API 502** | New-API 未启动 | `docker compose restart new-api` | 2 min |
| **API 504** | 上游慢 / 超时 | 后台换备用渠道 | 2 min |
| **HTTPS 过期** | certbot 未自动续期 | `sudo certbot renew` | 5 min |
| **数据库锁** | 磁盘满 / 进程死锁 | `docker compose restart mysql` | 5 min |
| **被刷 token** | Token 泄露 | 立即禁用 + 重置密码 | 10 min |

### 3.2 New-API 容器挂了

```bash
cd /opt/newapi

# 看日志找原因
docker compose logs new-api --tail 100

# 重启
docker compose restart new-api

# 还是不行就完全重建（数据不丢）
docker compose down
docker compose up -d
```

### 3.3 数据库崩溃

**症状**：所有 API 返回 500，错误含 "database" / "connection"

**解决**：
```bash
# 1. 重启 MySQL
docker compose restart mysql

# 2. 等 30 秒，看是否恢复
docker compose ps

# 3. 还是不行 → 从备份恢复
ls /opt/newapi/backups/mysql/
docker compose exec -T mysql mysql -uroot -p你的密码 new-api < 最新的备份.sql
```

### 3.4 VPS 整机挂了

**症状**：SSH 连不上、Dashboard 打不开

**解决**：
1. 用 Vultr/DO 控制台 → VNC 进系统
2. `docker compose up -d` 重启服务
3. 还是不行 → 用备份在新 VPS 上重建

**恢复时间**：30-60 分钟（数据不丢，有备份）

## 四、监控建议

### 4.1 UptimeRobot 监控

1. 注册 https://uptimerobot.com/
2. Add Monitor → HTTP(s)
3. URL: `https://api.你的域名.com`
4. 间隔：5 分钟
5. 告警：邮件 / 微信 / Telegram

    ports:
      - "3001:3000"
    volumes:
      - grafana-data:/var/lib/grafana

      - prometheus

## 五、扩展玩法

### 5.1 多用户管理

后台 → **用户管理** → 添加用户

每个用户：
- 独立 Token
- 独立额度
- 独立用量统计

适合团队 / 实验室场景。

### 5.2 限速配置

后台 → **系统设置** → **限速设置**

| 字段 | 建议 |
|------|------|
| 全局 RPM（每分钟请求）| 60 |
| 全局 TPD（每日 token）| 10000000 |

防止某个用户刷爆。

### 5.3 接入 Claude Code / Cursor 等

所有支持 OpenAI 兼容格式的工具都能接（参见 [04-客户端配置.md](04-客户端配置.md)）。

### 5.4 接入 MCP（Model Context Protocol）

在 New-API 后台：
1. 系统设置 → 启用 MCP
2. 配置 MCP 服务地址

## 六、成本控制策略

### 6.1 模型分流

后台 → **渠道管理** → 给不同模型设不同渠道优先级：

```
gpt-4o       → OpenAI（贵但强）
gpt-4o-mini  → OpenAI（便宜主力）
claude-sonnet-4.5 → Anthropic
deepseek-chat → DeepSeek（兜底便宜）
qwen-long    → 通义千问（长文本专用）
```

### 6.2 模型重定向

后台 → 系统设置 → 模型重定向：

| 原始 | 重定向 |
|------|--------|
| `gpt-4o` | `gpt-4o-mini`（如不需要顶级能力）|
| `claude-sonnet-4.5` | `deepseek-chat`（日常对话） |

⚠️ **谨慎**：会改变模型行为。

### 6.3 自动充值

某些平台支持 API 自动充值（需平台开启）：
- DeepSeek：API 充值
- OpenAI：自动充值（需绑卡）

## 八、备份策略

### 8.1 数据库备份（自动）

```bash
# 加入 crontab（每天凌晨 3 点）
crontab -e
0 3 * * * /opt/newapi/scripts/backup.sh
```

### 8.2 配置备份（手动）

```bash
# 备份 docker-compose.yml 和 .env
cp /opt/newapi/docker-compose.yml /opt/newapi/backups/config-$(date +%Y%m%d).yml
cp /opt/newapi/.env /opt/newapi/backups/env-$(date +%Y%m%d).env
```

### 8.3 异地备份

```bash
# 上传到云存储（如 Backblaze B2，免费 10GB）
rclone sync /opt/newapi/backups/ b2:newapi-backups/

# 或同步到另一台 VPS
rsync -avz /opt/newapi/backups/ user@backup-vps:/backups/
```
