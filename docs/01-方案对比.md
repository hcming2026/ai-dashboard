> 选型决策记录

## 二、详细分析

### One-API（❌ 不推荐）

**优点**：
- 项目老牌，逻辑稳定
- 上手最快

**缺点**：
- **已停止主动维护**（GitHub 最近一次 commit 较早）
- 新模型接入慢（如 GPT-5 / Claude 4.5 支持滞后）
- 安全漏洞未及时修复

**结论**：除非你已有深度定制的 fork，否则**新部署不建议选**。

---

### New-API（✅ 推荐）

**优点**：
- One-API 的事实继任者，**架构相似但功能更强**
- **协议转换**：同一 base_url 同时支持 OpenAI / Claude / Gemini 三种格式
- **用量统计**：按渠道、模型、用户、时间维度统计 + 成本计算
- **缓存计费**：理解各平台 prompt cache 计费规则（如 Anthropic cache hit 减免费用）
- **用户系统**：含 2FA、邀请码、配额、用户组
- **多支付**：内置 Stripe + EPay 充值（适合做团队分发）
- **Docker 一键起**

**缺点**：
- 许可证 **AGPL-3.0**（个人自用无影响；二次分发 / 闭源商用需谨慎）
- 部分高级功能（如 Claude 完整特性）需要看官方文档

**结论**：**个人自用 / 团队管理首选**。

---

### LiteLLM（⚠️ 适合开发者）

**优点**：
- Python 库，**完全可编程**
- 100+ 模型支持
- 适合嵌入到现有 Python 项目

**缺点**：
- 默认**没有 Web UI**，需要自行开发或使用第三方
- 用量统计需要自行实现
- 不适合"只想看看花多少钱"的非技术用户

**结论**：适合**会 Python、想把 LLM 网关嵌入自己产品**的开发者。

## 三、选 New-API 的具体理由

### 3.1 对你的需求最匹配

你的需求（回顾）：
- ✅ 看 GPT / Claude / DeepSeek 用量
- ✅ 统一 base_url
- ✅ 个人 / 团队自用
- ✅ 不要太复杂

New-API **直接覆盖**：
- Dashboard 自带用量统计（含金额换算）
- 一个 base_url 接入所有模型
- Docker 一键起，5 分钟跑通
- 不用写一行代码

### 3.2 抗"被掐断"风险

**多渠道冗余**：
- 同一模型可配多个渠道
- 某个平台挂了自动切备用
- 不依赖单一上游

**多 Key 轮询**：
- 单平台可配多个 API Key
- 自动轮询分散调用
- 防止单 Key 超额

### 3.3 长期可演进

部署一次后，未来可平滑升级：
- 加用户（团队场景）
- 加监控（Prometheus / Grafana）
- 加 CDN / 高可用
- 接入 MCP、自定义渠道

## 四、为什么不直接用各家官方 API？

| 用官方 API 的痛点 | 用 New-API 的解决 |
|-----------------|------------------|
| 每个平台单独看 Dashboard，**要切 5 个网站** | **一个 Dashboard 看所有平台** |
| 每个平台有独立 Key，**泄露一个 = 全泄露** | **Token 与上游 Key 隔离**，泄露 Token 可单独禁用 |
| 想换平台要改代码 | **只改 base_url**，不改代码 |
| 某平台挂了要等恢复 | **自动切换备用渠道** |
| 多人共用 Key 没法统计谁花了多少 | **每个 Token 独立统计** |

## 五、什么时候该考虑 LiteLLM？

如果你的需求超出 New-API 能力：

| 场景 | New-API | LiteLLM |
|------|---------|---------|
| 个人 / 小团队 | ✅ 推荐 | ⚠️ 杀鸡用牛刀 |
| 想嵌入 Python 项目 | ❌ | ✅ 推荐 |
| 需要 100+ 模型支持 | ⚠️ 看社区 | ✅ 推荐 |
| 自定义路由策略 | ⚠️ 有限 | ✅ 灵活 |
| 需要完全自主可控 | ❌ | ✅ |
