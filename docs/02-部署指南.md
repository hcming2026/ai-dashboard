# 部署指南

> 在已有 VPS（已完成 vps-setup 项目）上部署 New-API
> 预计耗时：30 分钟

---

## 前置条件

✅ 你已经搭好了 vps-setup 项目（任务 2）
✅ VPS 系统：Ubuntu 22.04 LTS
✅ VPS 已装 Docker（如果没有，请看下方"环境准备"）
✅ 一个域名（可选，但强烈推荐）

---

## 一、环境准备

### 1.1 安装 Docker（如果还没有）

SSH 连上 VPS（用 Tabby），执行：

```bash
# 一键安装 Docker
curl -fsSL https://get.docker.com | bash

# 把当前用户加入 docker 组（避免每次 sudo）
sudo usermod -aG docker $USER
newgrp docker

# 验证
docker --version
docker run hello-world
```

### 1.2 域名准备（强烈推荐）

**为什么需要域名**：
- ✅ HTTPS 加密（保护 API Key 不被窃取）
- ✅ 多客户端订阅链接
- ✅ 不会被 IP 变更影响

**最低成本方案**：
- 买一个 `.xyz` 域名（¥7/年）
- 推荐商家：Cloudflare Registrar / Namecheap / 阿里云
- 域名举例：`ai.你的名字.xyz`

**DNS 配置**：
- 在域名服务商后台添加 A 记录：`api.你的域名.xyz` → VPS IP
- 等待 DNS 生效（5-30 分钟）

## 二、部署 New-API（5 分钟）

### 方案 A：最快（用我的脚本）

在工作目录（如 `ai-dashboard/`）执行：

```powershell
# 在 Windows 上 PowerShell
cd "C:\Users\胡楚铭\WorkBuddy\2026-09-06-10-59-29\ai-dashboard"

# 上传到 VPS（替换为你的 VPS 用户和 IP）
scp -r configs/* root@你的VPS_IP:/opt/newapi/
```

然后在 VPS 上：

```bash
cd /opt/newapi
bash scripts/deploy.sh
```

### 方案 B：手动部署

#### 2.1 创建配置目录

```bash
# SSH 到 VPS
ssh root@你的VPS_IP

# 创建目录
mkdir -p /opt/newapi/{data,mysql,redis,nginx}
cd /opt/newapi
```

#### 2.2 下载 docker-compose.yml

```bash
curl -o docker-compose.yml https://raw.githubusercontent.com/你的用户名/ai-dashboard/main/configs/docker-compose.yml

# 或者用 nano / vim 创建文件，粘贴 configs/docker-compose.yml 的内容
```

#### 2.3 启动服务

```bash
cd /opt/newapi
docker compose up -d

# 查看启动状态
docker compose ps

# 查看 New-API 日志（确认启动成功）
docker compose logs -f new-api
```

**成功标志**：
```
new-api-1   | Server listening on :3000
```

## 三、初始化 New-API（5 分钟）

### 3.1 访问后台

浏览器打开：`http://你的VPS_IP:3000`

**默认账号**：
- 用户名：`root`
- 密码：`123456`

⚠️ **登录后立即修改密码**：右上角 → 系统设置 → 修改密码

### 3.2 关闭公开注册

后台 → **系统设置** → **用户注册设置** → **关闭注册**

避免被人扫到注册。

## 四、配置 HTTPS（10 分钟）

### 4.1 安装 Nginx + Certbot

```bash
sudo apt install nginx certbot python3-certbot-nginx -y
```

### 4.2 配置 Nginx 反向代理

```bash
sudo nano /etc/nginx/sites-available/new-api
```

粘贴 `configs/nginx.conf` 的内容（替换 `yourdomain.com` 为你的真实域名）。

启用配置：

```bash
sudo ln -s /etc/nginx/sites-available/new-api /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

### 4.3 申请 SSL 证书

```bash
sudo certbot --nginx -d api.yourdomain.com
```

按提示输入邮箱、同意条款。证书会自动续期。

**验证**：浏览器访问 `https://api.yourdomain.com`，看到 New-API 登录页 = 成功 ✅

## 五、安全加固（必须做，5 分钟）

### 5.1 修改默认端口（可选）

```bash
nano /opt/newapi/docker-compose.yml
# 修改 ports: "3000:3000" → "127.0.0.1:3000:3000"
# 只允许 Nginx 访问，不直接暴露端口
```

### 5.2 配置防火墙

```bash
# 只开必要端口
sudo ufw allow 22/tcp        # SSH
sudo ufw allow 80/tcp        # HTTP（Certbot 验证用）
sudo ufw allow 443/tcp       # HTTPS
sudo ufw enable
```

### 5.3 启用 2FA

后台 → 系统设置 → **两步验证** → 扫码绑定 Google Authenticator

### 5.4 设置环境变量（多机部署必做）

编辑 `docker-compose.yml`，加入：

```yaml
environment:
  - SESSION_SECRET=随机长字符串_用openssl-rand生成
  - CRYPTO_SECRET=另一个随机长字符串
```

生成随机字符串：
```bash
openssl rand -base64 32
```

## 八、常见问题

### Q1: Docker compose 启动失败

```bash
# 查看详细日志
docker compose logs new-api

# 重新构建
docker compose down
docker compose up -d --build
```

### Q2: Nginx 502 Bad Gateway

**原因**：New-API 还没启动 / 端口不对
**解决**：
```bash
docker compose ps        # 看 New-API 是否 running
curl http://127.0.0.1:3000    # 本地测试
```

### Q3: HTTPS 证书申请失败

**原因**：DNS 未生效 / 80 端口被占用
**解决**：
```bash
# 检查 DNS 解析
nslookup api.yourdomain.com

# 检查 80 端口
sudo lsof -i :80
```

### Q4: 忘记了 root 密码

```bash
# 进入容器重置
docker compose exec new-api /new-api reset
# 或者重新创建
docker compose down -v
docker compose up -d
```
